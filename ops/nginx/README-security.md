# Entrada de certificados y archivos privados: candidatos locales

Estos archivos no se instalan automáticamente ni reemplazan una configuración completa desconocida. Mantener `imbasac.cloud`, su frontend con hash, la reescritura `/api/` y la API SUNAT exclusivamente privada. Usar el inventario real y ensayo antes de activar.

1. Primera entrega compatible: usar configuración actual y flags nuevos apagados; no cargar todavía `application-security-template.yml`. El ejemplo externo activa TLS del puerto interno y requiere sus almacenes aunque las políticas estén apagadas.
2. Preparar PKI interna y pública conforme a [PKI](../pki/README.md), propietarios/lectura exactos y confianza diferenciada. La CA de dispositivos nunca se agrega como CA cliente del backend interno.
3. En ensayo, integrar `snippets/imbasac-client-mtls-server.conf` en el servidor HTTPS existente, sin duplicar directivas de Let's Encrypt. `optional` conserva roles exentos; el backend decide obligación y ACL después del login. Un certificado inválido puede hacer que Nginx rechace antes de conocer el usuario: no atribuir ese evento a una cuenta.
4. Reemplazar el proxy del `location /api/` por una integración revisada de `snippets/imbasac-backend-mtls-location.conf`. No añadir un segundo `proxy_pass`. Java exige mTLS, el proxy verifica nombre/CA del backend, Java verifica pin/EKU/URI del proxy y sólo entonces acepta IP/certificado reenviados. Sobrescribir headers de entrada, sin confiar en XFF del navegador. Si existe otro proxy real, inventariarlo antes de sustituir `$remote_addr`.
5. Ensayar y sustituir la entrada alternativa HTTP `pos` con `candidates/pos-deny-unknown-hosts.conf`. Conservar los servidores explícitos HTTPS y localhost; comprobar también hosts desconocidos, `www`, IPv6 y acceso directo.
6. Para los XML/CDR privados: aplicar la migración de catálogo `20261030_private_sunat_files.sql`, asignar permisos concretos, comprobar referencias/rutas reales y habilitar `security.sunat-files.enabled`. Publicar el frontend que utiliza HttpClient autenticado. Reemplazar **todos** los bloques alias `/sunat-files` antiguos por `snippets/imbasac-private-sunat-files-server.conf`. No desplegar esos botones con backend desactivado como una entrega operativa terminada: responderán 503 sin fallback público. La API privada es `/api/security/sunat-files/{xml|cdr}/{filename}`. Los PDF siguen sus flujos actuales; validar sus URLs reales antes del corte.
7. Preparar formato de log sin argumentos/cuerpos/Authorization; la nueva conexión SSE ya usa cabecera, no JWT en URL. Comprobar logs históricos y su retención privada sin copiar tokens al informe. Ejecutar `nginx -t` antes de recargar y comprobar las rutas reales después.

Pruebas locales de transporte: `tests/test_trusted_proxy.py` usa Nginx 1.24 real y servidor TLS aislado, certificados RSA y P-256. El backend tiene además una integración con Tomcat real que exige certificado cliente y comprueba sus atributos TLS. Las pruebas no acreditan el estado instalado en el VPS.

Habilitar en pasos separados la IP confiable, auditoría, administración y certificados por rol, con credenciales administrativas de recuperación y hardware homologado. No cambiar `CERTIFICATE_REQUIRED` a hash automáticamente ante un error.

La política de esta entrega aplica al rol completo. El piloto requerido con pocas cuentas se ensaya primero en entorno aislado; no cambiar CLIENTE en producción hasta preparar a todos los afectados. No existe selección parcial productiva por usuario dentro del rol; incorporarla exige una ampliación explícita antes de usarla.
